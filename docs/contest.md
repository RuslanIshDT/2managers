# Конкурс: что сдаём и как готовим

Задача: ИИ помощник руководителя, трек «Цифровой аватар». Постановка и требования — docs/tz.md.
Вопросы заказчику: Q&A 27.11 10:30 в МТС Линк, канал трека в Telegram (10:00–19:00).
Старт 26.11.2026 10:00 МСК, срок сдачи 28.11.2026 12:00 МСК (перенесён организаторами 26.11.2026, было 10:00). Цель — сдать к 08:00 МСК, с запасом.
Тексты требований — в form/form.json (title, hint), здесь — наши действия. id в скобках совпадает с form.json.

## Общие правила
- Выполняем обязательные поля: video, repo, done48, architecture, stack, cost, delivery, stand. Затем остальные: extra, prior.
- Сначала сквозной сценарий на стенде, затем остальное. Новые функции не начинать после вечера 27.11.
- Любая ссылка проверяется без входа в аккаунт до того, как попасть в value.
- В решении и видео — данные задачи. Публиковать их в репозитории, только если это разрешено.
- Заявлять только то, что видно на стенде. Не скрывать заглушки и несделанное: о них прямо спрашивает форма.

## Поля
**Демо-видео (video).** До 3 минут, один фрагмент, на данных задачи, снято на стенде. Ускорять можно только ожидание ответа модели; не вырезать, не склеивать, не подменять, без эффектов. Исходник без ускорения сохранить.
Готово: ссылка открывается без запроса доступа, показанное совпадает с done48.

**Репозиторий (repo).** Публичный, с историей. Коммиты небольшие и осмысленные, в main. Не переписывать историю и не закрывать доступ до объявления итогов (15.12.2026).
Готово: последний коммит сделан до срока, по README решение запускается.

**Дополнительные материалы (extra).** Примеры результатов, схема, итоги проверки качества. Без секретов и личных данных.
Готово: папка открыта по ссылке.

**1. Что сделано и что нет (done48).** Вести с начала спринта, в четырёх частях: работает и показано в видео; частично; на заглушках; не сделано.
Готово: каждый пункт «работает» проверен на стенде.

**2. Подход и архитектура (architecture).** Путь от запроса до ответа, инструменты, источники данных, где решает модель, чем проверяется ответ. Описание обновлять вместе с кодом.
Готово: описание совпадает с кодом, проверка ответа подтверждена замером на контрольных вопросах.

**3. Стек и модели (stack).** Модели, среда выполнения, фреймворки, базы данных, хостинг — с версиями. Выбирает владелец.
Готово: перечень совпадает с тем, что работает на стенде.

**4. Стоимость эксплуатации (cost).** С первого вызова модели записывать токены, время и цену. Форма сдачи требует стоимость одного запроса: считаем по каждому виду запроса — разбор письма, план дня, протокол встречи — плюс инфраструктура. Заполнить шаблон организаторов (ждём от владельца).
Готово: расчёт опирается на замеры, файл скачивается без входа.

**5. Запуск и поставка (delivery).** Состав поставки, среда, пример запроса и ожидаемого ответа. Запуск проверить в чистом окружении. Тестовый доступ владелец вписывает прямо в форму конкурса.
Готово: пример воспроизводится на стенде.

**Адрес стенда (stand).** Работает с 28.11 10:00 до 03.12 23:59; до 15.12 по запросу организаторов поднять за 24 часа. Питч 01.12.2026 — живая демонстрация на стенде и одной видеоплатформе, подключаем второго руководителя (M1); длительность и нужна ли презентация — ждём от владельца. Проверить из мобильной и обычной сети без VPN.
Готово: стенд открывается по HTTPS, сценарий из видео проходит.

**6. Наработки и компоненты третьих лиц (prior).** Каждую новую зависимость, модель, API и готовый материал вносить сразу, с лицензией. Сделанное до старта спринта — отдельно.
Готово: перечень сверен с файлами зависимостей.
